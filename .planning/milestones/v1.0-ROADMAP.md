# Milestone v1.0: Refatoração

**Status:** ✅ SHIPPED 2026-06-09
**Phases:** 1–3
**Total Plans:** 13

## Overview

Refatoração completa do código monolítico: paginação server-side, extração de hooks especializados e sub-componentes de 6 páginas grandes. Projeto reduzido de ~4000 linhas distribuídas em componentes inchados para módulos coesos com responsabilidade única.

## Phases

### Phase 1: Paginação de Questões

**Goal**: Fetch de questões usa paginação server-side com `.range()` em vez de carga única com `.limit(1000)`, eliminando o gargalo de memória e permitindo escala para qualquer volume de questões.

**Depends on**: Nothing

**Plans**: 3 plans

Plans:

- [x] 01-01: Service layer: fetchPaginatedQuestoes, fetchFilterOptions, progressive cache; QuestaoSkeleton component
- [x] 01-02: Hook refactor: pagination state, filter-to-query, AbortController, cache integration
- [x] 01-03: Page integration: skeleton during page transitions, pageLoading states

**Details:**

- PAGE_SIZE = 200 (payload leve sem muitas requisições)
- Cache flat progressivo sem TTL (substitui cache in-memory com 60s TTL)
- QuestaoSkeleton renderizado inline (não como overlay) — preserva contexto visual
- Filtros server-side: banca, orgão, cargo, ano
- Filtros client-side mantidos: assunto, carreira, status, objetivo

## Milestone Summary

**Key Decisions:**

- Ordem: Paginação → Hooks → Componentes (dependency chain natural: dados → hooks → UI)
- PAGE_SIZE = 200 (D-01)
- Cache flat progressivo sem TTL (D-03)
- Sub-componentes são puramente de apresentação (zero hooks, props-only)
- useQuestoes orquestrador compõe 3 hooks especializados com interface idêntica
